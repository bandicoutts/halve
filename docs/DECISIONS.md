- **2026-07-03 · AUTH-3: Onboarding display-name save upserts the profile row.** Live auth testing showed a successful sign-in could still land on `/onboarding`, and clicking **Save name** appeared to refresh the page. Root cause: the server action assumed the `profiles` row already existed and used `update(...).eq("id", user.id)`; if the auth user predated the `handle_new_user` trigger or the trigger missed, PostgREST can touch zero rows without surfacing an error, so the next server render still sees no `display_name`. Fix: `saveDisplayName` now `upsert`s `{ id: user.id, display_name }` with `onConflict: "id"`, relying on the existing `profiles_insert_own` / `profiles_update_own` RLS policies. The onboarding client also switches successful save/skip navigation to `router.replace(next)` without an immediate `router.refresh()`, avoiding a confusing reload of the onboarding route before navigation settles.
