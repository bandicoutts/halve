# Decision log (ADR)

Append-only. Newest first. One entry per decision: `date · decision · why`. Log decisions in the **same commit** as the code change.

---

- **2026-05-29 · Phase 2: Next.js 16 + Tailwind v4 + board UI.** `apps/web` scaffolded via `create-next-app` (App Router, Turbopack, `@parity/web`). Tailwind v4 CSS-first: `@import "@parity/design/tokens.css"` placed before `@import "tailwindcss"` so the Google Fonts URL import within tokens.css precedes all CSS rules (CSS spec requires `@import` first); `@theme inline` maps semantic tokens to Tailwind utilities (`bg-bg`, `text-fg-1`, etc.). Space Grotesk loaded via `next/font/google` (not tokens.css `@import url()`). Cell size computed post-mount via `useEffect` to avoid SSR/client hydration mismatch. Board component is pure layout (`Board.tsx`, `Cell.tsx`); all game state lives in `useGame` (reducer, error detection, tap-cycle, undo, hint) + `useTimer`. Theme toggle drives a `.dark` class on `<html>` — matching `tokens.css`'s `.dark` selector. Win banner fires 520ms after `isSolved` to let the final cell animation finish.
- **2026-05-29 · Vendored the Claude Design handoff (read-only) into `packages/design/handoff/`.** *Why:* it's the pixel + component + voice reference for Phase 2 UI work and only existed as an ephemeral Downloads zip; committing it makes the reference durable and discoverable. It is reference-only, not shipped — canonical tokens stay in `packages/design/styles` + `src` (see `handoff/VENDORED.md`).
- **2026-05-29 · Locked the design system from the Claude Design handoff into `packages/design` + DESIGN.md.** Canonical tokens live in `packages/design` (`styles/tokens.css` + typed `src/tokens.ts`); DESIGN.md holds the human-readable record. *Locked:* warm paper/ink duality (`#F6F1E8` / `#14110B`), fire as the single accent (`#B03E12` paper / `#E86B38` ink), water teal secondary, **Space Grotesk** as the sole typeface (tabular nums for changing numbers), 8pt spacing, restrained radii, soft warm shadows (hairlines on ink). Symbols are opposed teardrops (fire up / water down) with a flame+bridge+droplet master mark — no overlap. *Substitution flags to revisit:* Space Grotesk (no licensed face provided) and Lucide UI icons.
- **2026-05-29 · Symbols encoded as `0 = fire`, `1 = water`; edges as `{orientation:'h'|'v', r, c, kind:'eq'|'ne'}`.** *Why:* a compact, framework-agnostic representation the engine, design tokens (`SYMBOL`), and future Dart port can all share; matches the design handoff's data shape.
- **2026-05-29 · Engine solver is single-cell forced-move propagation (adjacency / balance / edge), uniqueness via independent backtracking.** *Why:* mirrors how a person reasons ("if this were fire we'd get three in a row, so it's water"), guarantees deduction-only with no guessing, and keeps uniqueness verification separate so it holds even for puzzles the human solver can't crack. Generator greedily removes givens while both checks pass; difficulty is scored from solver effort (empties + propagation passes + technique premiums), with easy/medium reached by revealing givens to a score setpoint. Validated by a 600-puzzle fuzz suite.
- **2026-05-29 · Tooling: pnpm workspaces, TypeScript strict (+`noUncheckedIndexedAccess`), Vitest for the engine.** *Why:* matches global TS conventions; Vitest is ESM-native and fast; `apps/web` (Next.js) + `supabase/` are stubbed now and built out in Phase 3 to keep this pass focused on tokens + engine.
- **2026-05-29 · Renamed to "Parity"; symbols changed from sun/moon to fire & water.** Supersedes the earlier "Lumen / refined-celestial" identity. *Why:* sun/moon is Tango's signature element and undercut the goal of an original stamp; and "Lumen" (a unit of light) only fit a celestial theme. *Now:* the name **Parity** is decoupled from the art (it names the balance rule), and the pieces are an amber-red **flame** vs cool teal **droplet** — genuine opposites mapping to the `≠` rule, with fire as the single hero accent. The earlier sun+moon master mark also failed the 44px squint test (muddy overlap); the new mark must read as one clean shape at small sizes. Folder + GitHub repo renamed `lumen` → `parity` (old URL auto-redirects).
- **2026-05-29 · Web-first, Flutter later, shared Supabase backend.** Lowest-risk path to a shippable, beautiful product; lets us nail design + engine once before porting.
- **2026-05-29 · Daily puzzle + unlimited practice mode.** Daily drives streaks/sharing (viral loop); practice drives replay. Covers both retention loops.
- **2026-05-29 · Build our own generator + solver (not a precomputed bank).** Infinite content; full control over uniqueness + deduction-only guarantee and difficulty scoring. 6×6 generation is cheap enough at runtime.
- **2026-05-29 · Supabase Auth from day one.** Streaks/stats must sync across devices, so accounts are foundational rather than retrofitted.
- **2026-05-29 · Social v1 = shareable result cards + personal streaks/stats. No leaderboards yet.** Sharing is the cheap virality win; leaderboards add backend cost without v1 payoff.
- **2026-05-29 · Fixed 6×6 grid; difficulty by deduction depth (not multiple sizes).** Cleanest, most premium; difficulty = clue count + required deduction techniques. 4×4 reserved for tutorial.
- **2026-05-29 · Stack: Next.js 16 + Tailwind + Supabase + Vercel; pnpm monorepo with shared TS engine + design-token packages.** Matches existing global Next.js/Supabase conventions; tokens centralized to avoid an "AI component-library" look.
- **2026-05-29 · Streaks/stats derived from a `solves` table, not denormalized.** Avoids premature denormalization; recompute is cheap at our scale.
- **2026-05-29 · Working title "Lumen"; refined-minimalism visual style; sun/moon symbols as custom vector art.** Final name + symbol direction to be locked in Phase 2.
