# Firebase Setup — Halve Mobile

One-time manual steps to wire Firebase Cloud Messaging (FCM) for push notifications.
The app runs without Firebase (no crash, no push support) until these steps are complete.

## 1. Create a Firebase project

1. Go to https://console.firebase.google.com → **Add project** → name it `halve`.
2. Enable **Google Analytics** → optional (not used by the app).
3. In the project, go to **Cloud Messaging** → enable the API if prompted.

## 2. Run flutterfire configure

```bash
cd apps/mobile
dart pub global activate flutterfire_cli  # once
flutterfire configure --project=<firebase-project-id>
```

Select **iOS** and **Android** platforms. This:
- Generates `lib/firebase_options.dart` (replaces the placeholder stub)
- Writes `ios/Runner/GoogleService-Info.plist`
- Writes `android/app/google-services.json`

The generated `firebase_options.dart` contains only public client-side values
(protected by Firebase security rules, not secrets) — commit it.

## 3. iOS: Push Notifications capability

In Xcode (`apps/mobile/ios/Runner.xcworkspace`):

1. Select the **Runner** target → **Signing & Capabilities** → **+ Capability** → add **Push Notifications**.
2. Add **Background Modes** → tick **Remote notifications**.
3. Edit `ios/Runner/Runner.entitlements` (create if absent):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>aps-environment</key>
    <string>development</string>
</dict>
</plist>
```

Change `development` → `production` for App Store / TestFlight builds.

## 4. Upload APNs key to Firebase

1. Apple Developer portal → **Keys** → create an APNs key (type: Apple Push Notifications service).
   Download the `.p8` key file and note the **Key ID** and **Team ID**.
2. Firebase console → **Project Settings** → **Cloud Messaging** → **Apple app configuration**
   → upload the `.p8` key.

## 5. Android: google-services.json

The file at `android/app/google-services.json` (generated by `flutterfire configure`) is
consumed by the `com.google.gms.google-services` Gradle plugin already wired in
`android/app/build.gradle.kts` and `android/settings.gradle.kts`. No further action needed.

## 6. Verify

```bash
flutter run        # local notifications (daily reminder) work without Firebase creds
flutter run --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...
```

On a real device (not simulator):
- Accept notifications on the firstrun flow
- Enable daily reminder in Settings → Notifications
- Confirm the notification fires at the set time
- Send a test FCM message from the Firebase console → should appear as a banner

## Notes

- **CocoaPods**: `flutter_local_notifications` doesn't yet support Swift Package Manager.
  The `[!] CocoaPods` deprecation notice in `flutter run` output is non-blocking and expected.
- **Simulator push**: iOS Simulator supports local notifications but not APNs/FCM.
  Test FCM delivery on a real device.
- **Permission model**: iOS uses provisional authorization (quiet delivery on first run,
  no aggressive banner prompt). Users upgrade to full permission via system Settings if desired.
  Android 13+ shows the OS POST_NOTIFICATIONS dialog on firstrun.
